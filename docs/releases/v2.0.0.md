# Monita Server v2.0.0

**Release date:** 2026-10-14  
**Status:** Stable server release, with Android and Home Assistant 2.0 staged separately.

## What's changed
- Chat @mentions are persisted and resolved before realtime delivery, improving consistency for threads and muted recipients.
- Channel owners and administrators retain valid message-control permissions without requiring a duplicate membership row. Assign, Resolve and Attach remain opt-in on individual messages.
- Uploaded attachments have an orphan-cleanup grace period, preventing live uploads from being deleted during concurrent maintenance.
- Added regression coverage for mention recipient membership, attachment lifecycle, message-control access, and orphan cleanup.
- Improved build/coverage validation and regenerated the API specification.

## Before upgrading
1. Back up the current Monita database **and** attachment storage.
2. Upgrade the Monita server first, then Home Assistant, then the Android client after its locally built 2.0 APK is verified.
3. Confirm Channel memberships, Chat history, archived messages, images and notification retention after restart.
4. Keep previous deployment image and database backup available for rollback.

**Compatibility:** Prior 1.3.x server clients and the 1.8.x Home Assistant integration retain legacy protocol fallbacks during the rolling upgrade. The complete 2.0 multi-client acceptance checks remain tracked in `docs/V2_RELEASE_GATE.md`.

## Download and update
The standard publish workflow produces Linux amd64/arm64 self-update runtimes, multiarch GHCR images, checksums and a source archive. Do not mark the server published until the release artifacts are present and the workflow succeeds.
